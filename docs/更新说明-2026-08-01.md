# 更新说明（2026-08-01）

本文记录 `mi-notic` 当前已提交版本相对于原有“通知转发”能力的主要更新。

## 本次新增

### 1. AI 修改记录

Cursor 和 Codex/ChatGPT 的 Hook 可以为每个完成轮次记录实际发生的文件变更，并通过飞书 Webhook 写入多维表格。

处理链路：

```text
任务开始
  → 临时 Git index 生成工作区快照
  → 任务完成后生成结果快照
  → 比较两棵 tree，汇总文件和增删行
  → 事件进入本地队列
  → worker 投递飞书 Webhook
```

记录仅包含需求摘要、结果摘要、文件状态、文件数量和增删行等元数据；不会保存完整 diff 或源码内容。

支持的文件状态包括新增、修改、删除和重命名，也会纳入暂存与未跟踪文件。

### 2. Git 提交记录

`watch:all` 现在会同时运行 Git 提交记录 worker。

该 worker 默认只读扫描 `D:/project` 目录下、最大深度为 5 的 Git 仓库。首次扫描仅建立各本地分支的基线；后续检测到新的本地 commit 时，生成独立事件并投递到 `FEISHU_COMMIT_WEBHOOK_URL`。

提交记录包含：

- 项目、仓库路径、远端地址和分支；
- 提交 SHA、父提交、作者、标题和说明；
- 修改文件、文件数、增删行与提交类型；
- 最近 7 天内修改过相同文件的 AI 记录事件 ID。

监听目标是本地 `git commit`，而不是远端 `git push`。一次提交只生成一条记录。

### 3. 控制台支持

仪表盘新增“修改记录”和“Git 提交记录”配置及状态展示，可查看是否已配置、待发送/失败/已发送数量、最近成功时间，并提供失败队列重放入口。

### 4. Windows 中文载荷兼容

修复了 Cursor Hook 在 Windows 环境中输入载荷偶发乱码时，导致“修改结果”字段无法正确读取的问题，并补充了对应回归测试。

## 配置

将以下配置写入 `.env.local`，不要提交该文件：

```dotenv
FEISHU_CHANGE_WEBHOOK_URL=https://example.com/change-record-webhook
FEISHU_CHANGE_WEBHOOK_TOKEN=可选的 Bearer Token
FEISHU_COMMIT_WEBHOOK_URL=https://example.com/commit-record-webhook
```

- `FEISHU_CHANGE_WEBHOOK_URL` 用于 AI 修改记录。
- `FEISHU_CHANGE_WEBHOOK_TOKEN` 可选；配置后以 Bearer Token 发送。
- `FEISHU_COMMIT_WEBHOOK_URL` 用于 Git 提交记录。

## 常用命令

```powershell
# 同时启动系统 toast、内部确认/提问 UI、AI 修改记录和 Git 提交记录
npm run watch:all

# AI 修改记录队列
npm run records:status
npm run records:dry-run
npm run records:replay

# Git 提交记录队列
npm run commits:status
npm run commits:dry-run
npm run commits:replay

# 运行自动化测试
npm test
```

`--dry-run` 只输出将投递的内容，不发送 Webhook；`replay` 会将失败队列重新放回待发送队列。

## 已知限制

1. AI 修改记录队列当前采用“读取 pending → 发送 → 移入 sent”的处理顺序。当常驻 worker 与手动 `--once` worker 同时处理同一事件时，可能造成重复投递。飞书侧应继续使用 `事件 ID` 去重。
2. Git 提交记录只扫描 `D:/project` 下的本地分支，不覆盖其他目录、远程分支或 push 事件。
3. Codex/ChatGPT 桌面端是否实际执行用户级 Hook 取决于客户端对 Hook 配置的加载与授权状态；本地采集和 Webhook worker 不会绕过该限制。
