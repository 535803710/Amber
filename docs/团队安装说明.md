# Amber 团队安装说明

部门推广入口以 [部门推广方案](部门推广方案调研与一期建设/【琥珀计划】部门推广方案调研与一期建设.md) 为准：**一条 npx 安装命令，重启 Cursor/Codex 后通过 Amber Skill 用自然语言完成接入、检查、修复和更新。**

Skill 与 npx 安装器尚未落地。本文记录的是仓库里**已经实现**的 Windows Runtime 安装（`team-setup` / `install.bat` / ZIP 构建）。这些能力会复用进 npx 安装器，**不是**发给部门同事的 SOP。

## 适用范围（当前 Windows 实现）

- Windows 10/11；
- Node.js 22 或更高版本；Codex 已安装时也可复用其本地 Runtime；
- Cursor 和 Codex；
- 已登录的 lark-cli 用户身份；
- 已获得 Amber 当前飞书 Base 的读取权限。

## 当前 Windows 安装器做什么

在仓库或解压目录执行 `install.bat`，或 `node scripts/team-setup.mjs install`，安装器会：

- 将运行文件同步到 `%LOCALAPPDATA%\Amber`（可用 `--target` 覆盖）；
- 创建本机 `.env.local`；
- 备份并合并 `%USERPROFILE%\.cursor\hooks.json`、`mcp.json`；
- 备份并合并 `%USERPROFILE%\.codex\hooks.json`；
- 更新 `%USERPROFILE%\.codex\config.toml` 的 `[mcp_servers.amber]`；
- 设置用户级 `AMBER_HOME`；
- 安装并启动 Amber 开机自启动，默认采用 `core` 档位。

安装完成后可打开本地控制台填写 AI/Git Webhook 和 Git 扫描目录。Reload Cursor，并重启 Codex 或新建任务。

安装过程不会覆盖其他 Hook、MCP、`.env.local` 或 `.local` 队列。Webhook 与 Token 只写入本机。配置备份位于 `<安装目录>\.local\setup-backups`。

自定义目录：

```powershell
node scripts/team-setup.mjs install --target "D:\Tools\Amber"
```

仓库内也可用 `npm run team:install`、`npm run team:doctor`、`npm run team:uninstall`。

### 已知限制：Codex Hook 的两层沙箱约束

当前安装器把安装进程使用的 Node 绝对路径写入 Cursor 和 Codex 的 Hook/MCP。若该路径是 `C:\Program Files\nodejs\node.exe`：

- Cursor 可以执行，AI 修改记录可正常采集；
- Codex 沙箱执行时报拒绝访问（`CreateProcessAsUserW` 错误 5），Hook 脚本不会启动，因此没有 baseline、队列和飞书投递；
- Hook 信任、新建任务不能改变该可执行文件权限。

本机探测：`codex sandbox -- "<node.exe>" --version`。系统 Node 会失败；Codex Runtime 下的 Node 可通过。安装器尚未按目标环境拆分 `cursorNode` / `codexNode`。`doctor` 目前只检查配置是否存在和安装器当前 Node，会出现假绿。

#### 2026-09-02 问题记录：切换 Node 后仍无 AI 修改记录

第一层 Node 权限修复后，Hook 命令已经能够启动；基线创建仍可能在 Git 快照阶段失败：

- Amber 使用临时索引执行 `git add -A` 生成轮次前后快照；临时索引只隔离 index 文件，Git 仍会向仓库 `.git/objects` 写入 blob/tree；
- Codex 沙箱对仓库元数据采用只读权限，错误包含 `insufficient permission for adding an object to repository database .git/objects`，因此 `UserPromptSubmit` 无法生成 baseline；
- 当前修复将快照对象写入 Amber 的 `.local/change-records/git-objects/<repo-hash>`，并将仓库原对象库作为只读 alternate。仓库 `.git` 无须写权限。

同一 Amber Hook 命令的端到端探针已完成 `begin → complete → sent`，单文件变更统计为 `+2/-0`，Webhook 返回 HTTP 200；完整 `node --test` 为 139/139 通过。

[Codex Hooks 官方文档](https://learn.chatgpt.com/zh-Hans/docs/hooks)确认 `UserPromptSubmit`、`Stop` 事件以及按 Hook 当前哈希记录信任。当前本机 Codex Desktop 0.152.0 还观察到：任务创建后再修改 Hook 并更新信任哈希，已打开的旧任务没有触发新的 `UserPromptSubmit`。这是本机兼容观察，Codex 升级后需要重新验证。验收时应先完成 Hook 信任，再创建全新任务。

## 维护者生成 ZIP（非部门分发入口）

```powershell
npm run build
```

使用当前工作区最新文件，未提交改动也会进入安装包。测试通过后生成 `dist/Amber-team-v<package.json 版本>.zip` 和同名 `.manifest.json`。清单记录版本、Git commit、工作区状态和 SHA-256。压缩包只含运行文件、`dashboard`、`docs` 和 `scripts`，不含 `.env`、`.env.local`、`.local`、`node_modules`、`.git` 或测试目录。

ZIP 用于维护者留存或本机对照，不作为部门推广包。

## 日常使用（已安装的 Runtime）

- 开机自启动会运行 Amber；也可双击安装目录中的 `amber.bat` 打开控制台、查看状态或手动启动监听。
- `amber.bat start` 启动 `core`：AI 修改采集、Git 提交采集和健康监控。
- `amber.bat start --full` 额外启动 Windows 系统通知和 UI 提示监听；切换档位时会重启 watcher。
- 在 Cursor/Codex 中直接描述“恢复上次现场”“查询之前的决定”或“修改前确认兼容约束”，Agent 会按需调用只读 `amber_get_task_context`。
- 通知和 Cursor 操作见 [Cursor 集成](cursor.md)；Codex 通知、MCP 参数和状态处理见 [Codex 集成](codex.md)。

MCP 默认使用当前共享 Base 和 AI/Git 两张记录表。团队需要切换数据源时，在安装目录的 `.env.local` 设置：

```dotenv
AMBER_BASE_TOKEN=<Base token>
AMBER_AI_TABLE_ID=<AI 修改记录表 ID>
AMBER_COMMIT_TABLE_ID=<Git 提交记录表 ID>
```

上述三项 MCP 数据源配置和 `AMBER_LARK_CLI_PATH` 会以 `.env.local` 为准；其他现有环境变量继续保持原加载规则。

## 验证

```powershell
cd $env:LOCALAPPDATA\Amber
.\amber.bat doctor
```

通过项包括运行文件、本地配置、Cursor/Codex Hook、Cursor/Codex MCP、lark-cli 用户登录，以及 AI/Git 两张 Base 表的读取权限。`doctor` 当前不验证 Codex 沙箱能否执行所写 Node，也不验证真实 Hook 基线和飞书投递。

需要提交脱敏诊断结果时运行：

```powershell
.\amber.bat doctor --json
```

JSON 仅包含检查状态、版本、运行档位和脱敏说明，不输出 Token、Webhook 或用户目录。

源码开发本机可用 `npm run watch:core` 后，在临时仓库做一次文档修改和一次提交，确认：

- Cursor 侧 AI 修改记录进入飞书；
- Git 提交记录进入飞书；
- 新建任务可以发现 `amber_get_task_context`；
- 相关历史查询返回证据，无强历史时返回 `no_strong_history`。

Codex Desktop 在系统 Node 写入 Hook 时，上述 AI 修改采集可能不会触发，见上文已知限制。

Codex 侧验收顺序：

1. 在 Hook 管理界面确认 Amber Hook 的当前定义均为已信任；
2. 信任完成后创建全新任务，提交一个会修改临时 Markdown 文件的请求；
3. 确认 `hook-health.ndjson` 依次出现 ChatGPT `begin`、`complete`；
4. 确认事件进入 `queue/sent`、Webhook 返回 2xx，且 `hook-errors.log` 没有 Node 启动或 `.git/objects` 权限错误。

部门试点验收按 [部门推广方案](部门推广方案调研与一期建设/【琥珀计划】部门推广方案调研与一期建设.md) 第八节，等 npx + Skill 落地后再执行。不要按解压 ZIP 做三人灰度。

## 升级与卸载（当前 Windows 实现）

重新运行 `install.bat` 或 `node scripts/team-setup.mjs install` 可覆盖升级，并保留 `.env.local`、`.local` 和其他 IDE 配置。

`uninstall.bat` 或 `node scripts/team-setup.mjs uninstall` 会移除 Amber Hook、MCP、用户环境变量和自启动。安装目录、配置、队列与备份继续保留。

## 常见问题

- `lark-cli` 找不到：确认命令可在 PowerShell 中执行，或在 `.env.local` 将 `AMBER_LARK_CLI_PATH` 指向 CLI 的 `run.js` 绝对路径；可解析的 `.cmd/.bat` shim 也会自动转换为 Node 入口。
- doctor 提示 `.cmd/.bat` 无法解析到 Node 入口：将 `AMBER_LARK_CLI_PATH` 改为对应 `run.js` 的绝对路径。
- 飞书登录失败：执行 `lark-cli auth status --json --verify` 检查当前用户身份和 token 状态，完成授权后重新运行 `amber.bat doctor`。
- Base 权限失败：确认成员对当前 Base 和两张记录表具有读取权限。
- IDE 没有 Amber 工具：Reload Cursor、重启 Codex 或新建任务，避免继续使用旧 MCP 进程。
- Webhook 投递失败：在本地控制台查看队列和最近错误，修正凭据后重放失败队列。
- Codex 改了文件但飞书没有 AI 修改记录：依次检查 Hook 当前哈希是否已信任、Node 能否通过 `codex sandbox -- "<该路径>" --version`、`hook-errors.log` 是否包含 `.git/objects` 权限错误，并在信任后创建全新任务复测。
