对比一：无 MCP 与第一次添加 MCP

验证历史证据层是否带来质量增益

质量：+8 分，90 → 98

  • 总平均分从 4.5 升至 4.9，满分回答从 13 个增加到 18 个。
  • 配置备份列表列结构、批次详情页 UI、Git 扫描范围配置、SSO 演练配置核对合计增加 10 分。
  • 新应用来源接入作为负向对照下降 2 分，说明首次引入 MCP 仍存在无强历史时的干扰风险。

效率：+10:07，26:29 → 36:36

  • 总耗时增加 38.2%，质量增益以明显延迟成本换取。
  • Cursor 由 14:12 增至 16:56；ChatGPT 由 12:17 增至 19:40。
  • 结论：首次 MCP 证明了质量价值，但调用范围和检索成本尚未收敛。

对比二：第一次添加 MCP 与优化后 MCP

验证调用门控与检索优化是否有效

质量：+2 分，98 → 100

  • Cursor 从 49 / 50 提升到 50 / 50；ChatGPT 同样从 49 / 50 提升到 50 / 50。
  • 第二轮唯一回落的负向对照恢复满分，第三轮 20 个回答全部满分。
  • 9 个应调用题均调用，1 个不应调用题均未调用；两模型决策准确率均为 10 / 10。

效率：−5:26，36:36 → 31:10

  • 总耗时下降 14.8%，并在质量更高的前提下回收了一半以上的首次新增耗时。
  • Cursor 总耗时从 16:56 降至 13:25；ChatGPT 从 19:40 降至 17:45。
  • 结论：优化不是单纯减少调用，而是在正确调用决策下减少了无效或冗余的检索成本。

最终判断

Amber MCP 应定位为按需启用的历史证据层

第三轮给出了本批样本中的最佳结果：质量从无 MCP 的 90 分提升至 100 分，同时比首次 MCP 缩短 5 分 26 秒。它并非通用推理加速器：相对无 MCP 仍多耗时 17.7%，因此产品关键不是“始终调用”，而是仅在任务依赖历史决策、提交链或演变过程时调用，并以当前代码、Git 与测试作为最终事实依据。
